Drive a differential-drive robot with WASD. A simulated 2-D LiDAR raycasts the true map; a log-odds occupancy grid is built from the particle-filter pose estimate, not from ground truth, so mapping and localisation error interact exactly as they do in real grid SLAM.

Guide — SLAM Mapping Visualizer

1 · What is simulated

A differential-drive robot (body radius 0.10 m) drives through a 7.5 m × 7.5 m line-segment world. Everything runs in the browser from a seeded PRNG: there is no recorded dataset and no hardware in the loop. Three estimates of the pose are tracked at once — ground truth (green), wheel odometry alone (dead reckoning) and the particle-filter estimate (amber) that the map is actually built from.

2 · Driving & physics

W / S
Accelerate forward / reverse at 2.0 m/s², capped at 1.10 m/s forward and 0.60 m/s in reverse.
A / D
Angular acceleration 4.0 rad/s², capped at ±2.2 rad/s (86 °/s).
Timestep
Fixed Δt = 1/60 s integrator with an accumulator, so the physics is frame-rate independent. Released controls decay exponentially (3 s⁻¹ linear, 6 s⁻¹ angular).

3 · LiDAR model

360 beams over 360° (1.0° increment), 6.0 m maximum range, scanning at 10 Hz — roughly an RPLIDAR A1 class sensor. Each beam is raycast analytically against the true wall segments (ray/segment intersection), then corrupted with σr = 2 cm Gaussian range noise and σθ = 0.25° Gaussian bearing noise. Beams that reach 6.0 m without an intersection are reported as max-range returns: they carve free space but never mark an obstacle.

4 · Occupancy grid (mapping)

A 150 × 150 grid of 5 cm cells stores log-odds l = log(p / (1 − p)), initialised at 0 (p = 0.5, unknown). For every beam the cells along the free portion are updated with l += l_free = −0.40 (inverse-sensor probability 0.40) and the endpoint cell with l += l_occ = +0.85 (probability 0.70); values are clamped to [−5, +5], i.e. p ∈ [0.007, 0.993]. The map panel renders p = 1 − 1/(1 + eⁿ) directly as a grey scale — dark grey is confidently free, light grey confidently occupied, and slate blue is a cell that has never been observed.

5 · Odometry drift & the particle filter

Wheel odometry is deliberately imperfect: a +3% translation scale error, 8% proportional noise on each translation increment, 6% on each rotation increment and a +0.15 °/s gyro bias. Integrated open loop it walks away from the truth — that is the orange curve on the error chart.

Monte-Carlo localisation with 300 particles corrects it. Each 10 Hz cycle the particles are propagated with the textbook odometry motion model (δrot1, δtrans, δrot2 with noise coefficients α1..4 = 0.02, 0.02, 0.02, 0.005), then weighted by an endpoint likelihood field: 30 sub-sampled beams are projected from each particle and scored as w ∝ ∏ (0.85·p_occ + 0.15), where p_occ is the maximum occupancy probability in the 3 × 3 neighbourhood of the endpoint cell (a one-cell-σ approximation of a true distance-transform likelihood field). Cells that have never been observed carry no information and are skipped; if fewer than 8 beams land on known cells the weights are left untouched and the filter coasts on odometry. Low-variance (systematic) resampling fires whenever the effective sample size Neff = 1/Σw² drops below N/2 = 150.

6 · Honest limitations

There is no loop closure and no pose-graph optimisation in this demo. Nothing detects a revisited place, and no back-end ever re-optimises past poses, so any error the filter accumulates stays in the map. Real systems (Cartographer, GMapping + scan matching, RTAB-Map) add branch-and-bound scan matching, loop-closure constraints and sparse pose-graph optimisation on top of exactly this front end. The measurement model also scores against the map the robot itself built, so a bad pose can corrupt the map and a corrupt map can then reinforce a bad pose.

Algorithm Executing

C++ · one pass per scan 
// ParticleFilterSlam::step() — one LiDAR scan
void step(const Odometry& u, const LaserScan& z) {

  // 1 · motion model: push every hypothesis
  for (Particle& p : particles_)
    p.pose = sampleMotionModel(u, p.pose, alpha_);

  // 2 · measurement model: score against the map
  for (Particle& p : particles_) {
    p.logW = 0.0;
    for (const Beam& b : subsample(z, kBeamStep))
      p.logW += std::log(kZHit * likelihoodField(p.pose, b, grid_)
                         + kZRand);
  }

  // 3 · normalise, then measure cloud health
  normaliseWeights(particles_);
  const double nEff = 1.0 / sumOfSquaredWeights(particles_);

  // 4 · resample only once the cloud collapses
  if (nEff < 0.5 * kNumParticles)
    particles_ = lowVarianceResample(particles_);

  // 5 · pose estimate = weighted mean of the cloud
  pose_ = weightedMean(particles_);

  // 6 · fuse the scan into the log-odds grid
  for (const Beam& b : z)
    grid_.integrate(pose_, b, kLogOddsOcc, kLogOddsFree);
}

Methodology & assumptions

What this models

A 2-D grid-SLAM front end running live in the browser. A differential-drive robot moves through a 7.5 m × 7.5 m line-segment world under a fixed 1/60 s integrator. Ten times a second a simulated 360-beam LiDAR is raycast analytically against the true walls and corrupted with range and bearing noise. Wheel odometry is integrated with a scale error, proportional noise and a gyro bias, and a 300-particle Monte-Carlo localisation filter corrects it against the map built so far. The occupancy grid is updated with a log-odds inverse sensor model from the filter estimate, so localisation and mapping error feed back into each other as they do on a real robot.

Key assumptions

  • World 600 units = 7.5 m; robot body radius 0.10 m; walls are infinitely thin segments.
  • LiDAR: 360 beams over 360° (1.0°), max range 6.0 m, 10 Hz, σrange = 0.02 m, σbearing = 0.25°, no beam dropout, no mixed pixels, no incidence-angle effects.
  • Grid: 150 × 150 cells of 0.05 m; l_occ = +0.85 (p = 0.70), l_free = −0.40 (p = 0.40), clamped to [−5, +5].
  • Odometry: +3% translation scale error, 8% proportional translation noise, 6% proportional rotation noise, +0.15 °/s gyro bias.
  • Filter: 300 particles, motion-model coefficients α1..4 = 0.02 / 0.02 / 0.02 / 0.005, 30 sub-sampled beams, zhit = 0.85, zrand = 0.15, resample when Neff < 150.
  • Drive limits: 1.10 m/s forward (0.60 m/s reverse), 2.2 rad/s, 2.0 m/s² and 7.0 rad/s². Deterministic mulberry32 PRNG, seed 1337, reseeded on every environment load.

Formulas & references

  • Log-odds update: lₜ = lₜ₋₁ + log(p(m|z) / (1 − p(m|z))) − l₀, with l₀ = 0 and the inverse sensor model reduced to the two constants above; display probability p = 1 − 1/(1 + eⁿ).
  • Odometry motion model: δₕₒₜ₁, δₜₕₐₙₛ, δₕₒₜ₂ decomposition with σ² = α₁δ²ₕₒₜ + α₂δ²ₜₕₐₙₛ (Thrun, Burgard & Fox, Probabilistic Robotics, Table 5.6).
  • Measurement model: endpoint likelihood field, w ∝ ∏ₖ (z_hit·p_occ(xₖ) + z_rand), p_occ taken as the 3×3 neighbourhood maximum (σ ≈ one cell) instead of a distance transform.
  • Low-variance resampling and N_eff = 1 / Σ w² (Doucet et al., 2000; Grisetti, Stachniss & Burgard, 2007, Improved Techniques for Grid Mapping with Rao-Blackwellized Particle Filters).
  • Moravec & Elfes (1985), High Resolution Maps from Wide Angle Sonar; Thrun, Burgard & Fox (2005), Probabilistic Robotics, ch. 8–9.

Limitations

  • No loop closure and no pose-graph optimisation. Nothing detects a revisited place and no back-end re-optimises past poses, so accumulated error is baked into the map permanently.
  • Rao-Blackwellised SLAM would carry one map per particle; here all particles score against a single shared map, which understates the filter's true uncertainty.
  • The likelihood field is a 3×3 maximum rather than a Euclidean distance transform, so the weight surface is coarse and flat-cornered.
  • Kinematics only: no wheel slip, no inertia or mass, no motor dynamics. Collisions are resolved geometrically — the blocked axis is dropped so the body slides along the wall — not by contact forces.
  • 2-D, static world with perfectly reflective thin walls; no dynamic obstacles, no glass or specular surfaces, no multipath, no sensor dropout.
  • Coverage is measured against the bounding box of the current environment, which includes cells inside walls that can never be observed, so 100% is not reachable.
Browser simulation for education. Timings, register values and sensor models are idealised approximations and are not hardware-validated.
