    Guide — Terminal Heist

    1 · What this is

    A fictional puzzle sandbox running an emulated POSIX shell in the browser. Nothing here touches a real machine: the filesystem, the process table and the “network” are all JavaScript objects. Each of the four levels is a small forensic task solved with ordinary Unix commands. Type in the prompt at the bottom of the terminal and press Enter.

    2 · Filesystem & navigation

    pwd
    Print the absolute working directory.
    ls [-l -a -h -1 -F -R] [path…]
    -l gives the real long format: mode string, link count, owner, group, size, date, name. -a also shows . and ...
    cd [path]
    Handles .., ., ~, - (previous directory), absolute and relative paths. No argument returns home.
    cat / head / tail
    cat FILE…, head [-n N] FILE, tail [-n N] FILE. Default 10 lines.
    find [path] [-name PAT] [-type f|d] [-perm MODE] [-maxdepth N]
    Pre-order walk; unreadable directories are reported, not skipped silently.
    grep [-i -n -r -l -v -c] PATTERN FILE…
    Basic regular expressions, falling back to a literal match if the pattern will not compile. Globs such as logs/* are expanded by the shell.
    echo [-n] ARGS
    Expands $USER, $HOME, $PWD, $SHELL, $HOSTNAME, $PATH.

    3 · Permissions & processes

    Every node carries a 12-bit mode, an owner and a group, and the checks are enforced exactly as on Unix: read to open a file or list a directory, write to modify it, execute on a directory to traverse into it. A directory with r but no x can be listed but not entered — that distinction is the point of level 3. root bypasses the read and write checks, as it does on a real system.

    chmod MODE FILE…
    Octal (chmod 644 f, chmod 0700 d) and symbolic (chmod u+r f, chmod a-w,g+X d).
    chown [USER][:GROUP] FILE…
    Root only; anyone else gets Operation not permitted.
    ps [aux|-e|-ef]
    Bare ps shows your processes on this terminal; ps aux shows the whole table.
    kill [-9|-15|-SIG] PID…
    You may only signal your own processes unless you are root.
    whoami / id / history / man CMD
    Identity, the numbered command history, and a manual page for every command above.

    6 · Scoring

    Each checklist item is worth 100 points as you complete it. Finishing a level adds 1000 + max(0, 500 − 10×commands) + max(0, 300 − 50×hints) + max(0, 200 − seconds), which sets the rank (S ≥ 1500, A ≥ 1200, B ≥ 900). The running score carries across levels; Retry rewinds it to the value it had when the level started, so a retried level can never be farmed for points.

    Methodology & assumptions

    What this models

    A single-process POSIX shell emulator. The virtual filesystem is a tree of typed nodes — {t:'f'|'d', mode, owner, group, mtime, content|children} — rooted at / with /bin, /etc, /home, /root, /tmp and /var/log mounted under it and the level's puzzle data grafted into the user's home directory. The command parser tokenises the input line (quote-aware), expands ~, $VAR and */? globs, splits the leading option cluster into flags, and dispatches to a handler table. The permission model resolves each path component in turn, requiring the execute bit on every directory it traverses and the relevant r/w/x bit on the target, with the owner / group / other triad selected exactly as stat(2) does. The architecture is event driven: a single keydown listener on the input owns the line editor (history, Ctrl+L, Ctrl+C), handlers mutate one GAME_STATE object, and every state change re-renders the mission panel, the status strip and the nav pills instead of the DOM being poked from inside command code.

    Key assumptions

    • Single user session, no fork, no pipes, no redirection, no job control, no environment inheritance: one command per line.
    • Modes are 12-bit; the sticky bit is rendered on /tmp (1777) but only the nine permission bits are enforced. No ACLs, no capabilities, no setuid.
    • Group membership is a single supplementary group per level (staff), not a list.
    • root bypasses read and write checks and needs one execute bit to execute, matching Linux behaviour.
    • The process table is static per level apart from kill; PID 1 ignores every signal. %CPU and %MEM are fixed decorative constants.
    • File timestamps are fixed strings, so ls -l dates are stable rather than live.
    • Levels: 1 ls/cat/grep, 2 grep -r over logs, 3 chmod on a write-only file and a non-traversable directory, 4 ps/kill/chown/chmod as root. Every win condition is reachable with the commands the guide documents.

    Formulas & references

    • Access check: bits = owner==user ? mode>>6 : group==usergroup ? mode>>3 : mode, then bits & 4|2|1 for r|w|x — POSIX.1-2017 File Access Permissions; Linux path_resolution(7), inode(7).
    • Symbolic mode grammar [ugoa]*[-+=][rwxX]* applied left to right over comma-separated clauses, X setting execute only for directories or files that already have an execute bit — GNU coreutils chmod(1).
    • ls -l block total is Σ 4×⌈size/4096⌉ KiB, matching a 4 KiB block filesystem; link count is 2 + subdirectories for a directory and 1 for a regular file.
    • Diagnostics follow bash and coreutils wording: bash: foo: command not found, cat: x: No such file or directory, ls: cannot open directory 'x': Permission denied, bash: kill: (7) - Operation not permitted.
    • Caesar shift of −2 over A–Z with wraparound for the level-3 tokens.
    • Kernighan & Pike (1984), The UNIX Programming Environment; Stevens & Rago (2013), Advanced Programming in the UNIX Environment, ch. 4.

    Limitations

    • Not a shell: no pipelines, redirection, subshells, globbing beyond * and ?, quoting subtleties, exit statuses or signals other than what kill pretends to send.
    • Commands are re-implementations, not the real utilities — only the flags listed in the guide exist, and grep uses JavaScript regular expressions rather than POSIX BRE.
    • No inodes, hard links, symlinks, mounts, timestamps that update, or disk quotas; ls -l sizes are string lengths.
    • The network in level 4 is a scripted three-step dialogue, not a protocol; nothing is transmitted anywhere.
    • Progress is not persisted — only the sound preference is stored in localStorage. Reloading restarts at level 1.
    • The side panel is hidden below 1024 px, so on a phone the mission checklist lives behind the objective command.
    Browser simulation for education. This is a fictional puzzle sandbox: the hosts, files, processes and “vault” are invented, the emulated commands are approximations of the real utilities, and nothing here connects to or describes a real system.
