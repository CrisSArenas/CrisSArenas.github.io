Guide — STM32 Memory-Mapped I/O Lab

1 · What this is

A bit-level model of the STM32F407 (Cortex-M4F, 168 MHz, 1 MB flash, 192 KB SRAM). There is no CPU here: you write the peripheral registers directly, exactly as bare-metal firmware does, and the lab shows the resulting 32-bit value in hex and binary, the equivalent CMSIS C statement, the pin states and an idealised waveform. All addresses and bit positions follow RM0090.

APB1 = 0x40000000, APB2 = 0x40010000, AHB1 = 0x40020000. Every peripheral is clock-gated: until the matching bit in RCC->AHB1ENR (+0x30), APB1ENR (+0x40) or APB2ENR (+0x44) is set, its registers read back 0 and writes are lost. That is the single most common bare-metal bug, so the lab warns you when the clock for the selected peripheral is off.

3 · GPIO recipe

Offsets from the port base: MODER +0x00 (2 bits/pin: 00 input, 01 output, 10 alternate function, 11 analog), OTYPER +0x04, OSPEEDR +0x08, PUPDR +0x0C, IDR +0x10, ODR +0x14, BSRR +0x18, AFRL +0x20, AFRH +0x24.

To make PA5 (the Nucleo user LED) a push-pull output you clear then set its two mode bits:

RCC->AHB1ENR |= (1U << 0);   GPIOA->MODER &= ~(3U << (5*2));   GPIOA->MODER |= (1U << (5*2));

BSRR is the atomic way to drive a pin: writing 1 to a bit in the low half word (BS0..BS15) sets the matching ODR bit, writing 1 to the high half word (BR0..BR15) clears it. It is write-only and always reads 0, so no read-modify-write race with an interrupt handler. AFRL/AFRH use 4 bits per pin to pick the alternate function: AF1 = TIM2, AF5 = SPI1, AF7 = USART1/USART2.

4 · USART2 baud arithmetic

With 16× oversampling (OVER8 = 0), USARTDIV = fPCLK / (16 × baud). USART2 hangs off APB1, so PCLK1 = 42 MHz. For 115200 baud:

USARTDIV = 42 000 000 / (16 × 115 200) = 22.786

The mantissa is the integer part, 22 = 0x16, and the fraction field counts sixteenths: round(0.786 × 16) = 13 = 0xD. So BRR = (22 << 4) | 13 = 0x16D, and the realised baud rate is 42e6 / (16 × 22.8125) = 115 068 baud, a −0.11% error — well inside the ±2% a UART receiver tolerates. Registers: SR +0x00 (TXE bit 7, RXNE bit 5), DR +0x04, BRR +0x08, CR1 +0x0C (UE 13, TE 3, RE 2).

5 · SPI1

CR1 +0x00: CPHA 0, CPOL 1, MSTR 2, BR[2:0] 3–5, SPE 6, LSBFIRST 7, SSI 8, SSM 9, DFF 11. SR +0x08: RXNE 0, TXE 1, BSY 7. The serial clock is fSCK = PCLK2 / 2(BR+1), so from 84 MHz the divider runs from /2 (42 MHz) to /256 (328 kHz). CPOL sets the idle level of SCK; CPHA picks whether data is sampled on the first or the second edge of each cycle.

6 · NVIC, the vector table and interrupt entry

Interrupt n is enabled by setting bit n mod 32 of ISER[n / 32], where ISER0 lives at 0xE000E100 (ISER1 at 0xE000E104) and the mirrored clear-enable array ICER0 at 0xE000E180. On this part EXTI0 is IRQ 6 (bit 6 of ISER0), TIM2 is IRQ 28 (bit 28 of ISER0) and USART2 is IRQ 38, which is bit 38 mod 32 = 6 of ISER1. A pin interrupt also needs SYSCFG (0x40013800) to route the port to the EXTI line and EXTI (0x40013C00) to unmask it and pick the edge.

Priority lives in the byte array at 0xE000E400 (IPR), one byte per IRQ. The STM32F4 implements only the top 4 bits of that byte, so there are 16 levels and 0 is the most urgent. SCB->AIRCR.PRIGROUP splits those 4 bits into pre-emption and sub-priority; the CMSIS default on ST parts is group 4 — all 4 bits pre-emption, no sub-priority — so any higher-priority IRQ pre-empts a running handler and equal priorities never pre-empt each other.

Entry flow. The vector table starts at the address in SCB->VTOR (0xE000ED08, 512-byte aligned): offset 0x00 holds the initial main stack pointer, offset 0x04 the reset handler, then the 14 system exceptions, with IRQ n at 0x40 + 4n. When an enabled interrupt fires, hardware pushes eight words (xPSR, PC, LR, R12, R3–R0) onto the current stack, loads LR with an EXC_RETURN pattern, fetches the handler address from the vector table and switches to handler mode on the MSP. That is about 12 cycles ≈ 71 ns at 168 MHz; tail-chaining a second pending interrupt costs roughly 6. With the FPU active, lazy stacking reserves but does not fill another 18 words.

7 · SysTick and timing

CTRL 0xE000E010 (ENABLE 0, TICKINT 1, CLKSOURCE 2, COUNTFLAG 16), LOAD 0xE000E014, VAL 0xE000E018. The 24-bit counter decrements to zero and reloads, so the tick period is (RELOAD + 1) / fSysTick where f is the core clock (CLKSOURCE = 1, 168 MHz) or core/8 (CLKSOURCE = 0, 21 MHz). A 1 kHz RTOS tick from 168 MHz therefore needs RELOAD = 168 000 − 1 = 167 999. One core cycle is 1/168 MHz ≈ 5.95 ns; every cycle figure in this lab uses that number.

8 · Using the lab

Peripheral tabs
Load that block's registers into the editor. Tabs are buttons — Tab and Enter work.
Bit cells
Click (or focus and press Enter/Space) to toggle. Reserved bits are inert. Hover for the field name, bit range, current value and meaning.
Under each register
The value in hex, the same value in binary, and the C statement that would produce it.
BSRR
Clicking a BSRR bit performs the write: the low half sets an ODR bit, the high half clears it, and BSRR itself falls straight back to 0 — the real hardware behaviour.
Presets
Six worked configurations, each of which also sets the RCC clock-enable and alternate-function bits it needs.

Quick Guide

STEP 1

Enable the clock

Open RCC and set the peripheral's bit in AHB1ENR / APB1ENR / APB2ENR. Nothing responds until you do.

STEP 2

Select a peripheral

Choose GPIOA, TIM2, USART2, SPI1, ADC1 or NVIC/SysTick to load its registers.

STEP 3

Toggle bits

Click any bit to flip it. Hex, binary, the C line, the pin map and the waveform update instantly.

STEP 4

Read the waveform

Idealised scope: GPIO levels, PWM period and duty, a UART frame, SPI SCK/MOSI, ADC sampling, the SysTick ramp.

STEP 5

Try the presets

LED, PWM 1 kHz, UART 115200, SPI 2.6 MHz, ADC, SysTick 1 kHz — each one is a complete, correct register sequence.

Methodology & assumptions

What this models

A bit-accurate model of seven STM32F407 register blocks — RCC, GPIOA, TIM2, USART2, SPI1, ADC1 and the Cortex-M4 SysTick/NVIC core registers. Every register is stored as a 32-bit word; toggling a bit recomputes the field values, the hex and binary view, the equivalent CMSIS C statement, the port A pin map and an idealised waveform for that peripheral. Addresses, offsets, bit positions, reset values and alternate-function numbers are taken from RM0090 and the Cortex-M4 generic user guide; nothing is executed, so there is no CPU, no bus timing and no analogue behaviour.

Key assumptions

  • STM32F407, Cortex-M4F at 168 MHz from HSE 8 MHz through the PLL (M 8, N 336, P 2). AHB 168 MHz, APB1 42 MHz, APB2 84 MHz. One core cycle = 5.95 ns.
  • APB prescalers are > 1, so the APB timer clocks are doubled: TIM2–TIM7 run at 84 MHz, TIM1/8/9/10/11 at 168 MHz.
  • USART2 is on APB1, so its PCLK is 42 MHz; SPI1 and ADC1 are on APB2 at 84 MHz, and ADCCLK is PCLK2/4 = 21 MHz (within the 36 MHz maximum).
  • Reset values are the real ones: GPIOA->MODER = 0xA8000000 and PUPDR = 0x64000000 (PA13–PA15 are the SWD/JTAG pins), TIM2->ARR = 0xFFFFFFFF, USART2->SR = 0x00C0, SPI1->SR = 0x0002, RCC->AHB1ENR = 0x00100000.
  • Clock gating is enforced as a warning, not a lockout: the lab flags a peripheral whose RCC enable bit is clear instead of silently discarding writes, so you can still explore the register layout.
  • Waveforms are drawn from the register values only. They are geometrically exact (period, duty, bit order, clock phase) but carry no propagation delay, rise time, jitter, noise or bus contention.

Formulas & references

  • GPIO: MODER 2 bits/pin, AFRL/AFRH 4 bits/pin, so pin p uses (1U << (p*2)) and (af << ((p%8)*4)). BSRR low half sets, high half resets, atomically.
  • Timer: f_CNT = 84 MHz / (PSC+1), f_PWM = f_CNT / (ARR+1), duty = CCR1 / (ARR+1). The 1 kHz preset is PSC 83, ARR 999, CCR1 500.
  • USART: USARTDIV = f_PCLK / (16 × baud); BRR = mantissa in [15:4] and round(frac × 16) in [3:0]. 42 MHz at 115200 gives 22.786 → 22 and 13 → BRR = 0x16D.
  • SPI: f_SCK = PCLK2 / 2^(BR+1); frame time = bits / f_SCK.
  • ADC: tconv = (SMP + 12) ADC cycles at 12-bit resolution, i.e. 96 cycles ≈ 4.6 µs at 21 MHz with SMP = 84.
  • NVIC: IRQ n → bit n mod 32 of ISER[n / 32]; priority byte at 0xE000E400 + n, only the top 4 bits implemented.
  • SysTick: period = (RELOAD+1) / f, f = 168 MHz or 168/8 = 21 MHz.
  • ST RM0090 rev 21, STM32F405/407/415/417 reference manual; ST PM0214, STM32 Cortex-M4 programming manual; Yiu (2013), The Definitive Guide to ARM Cortex-M3 and Cortex-M4 Processors.

Limitations

  • No instruction execution, no bus matrix, no wait states, no DMA and no flash ART accelerator; nothing here predicts real firmware throughput.
  • Only a subset of each block's registers is exposed, and a few rarely used bits inside them are shown as reserved.
  • The package drawing is an illustrative LQFP-48 footprint used to visualise port A; the STM32F407 actually ships in LQFP-100/144/176 and its pin assignment differs.
  • ADC1->DR is writable here so the sampling view has something to show; on hardware it is read-only and driven by the converter. The analogue input is a fixed two-tone waveform, not a model of any sensor.
  • Status flags (TXE, RXNE, BSY, EOC, COUNTFLAG) are free-running bits you set by hand; no peripheral state machine sets or clears them for you.
  • Interrupt latency, tail-chaining and lazy FPU stacking are quoted from the ARM documentation, not simulated.
Browser simulation for education. Timings, register values and sensor models are idealised approximations and are not hardware-validated. Always check RM0090 and the datasheet before writing production firmware.
