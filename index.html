About

I am a Quantitative Investment Professional and AI Engineer with 6+ years of experience across institutional investing, applied AI, quantitative research, and data science in the United States, Europe, and Latin America.

My work sits at the intersection of AI and portfolio management. I design and build agentic AI systems that operate inside investment workflows. Multi-agent systems monitor portfolios, read GP reports, DDQs, and manager letters, extract data with a citation back to the source, and draft research for review. Every system I build carries monitoring, guardrails, human-in-the-loop approval, and a full audit trail, because in investing an answer you cannot trace is worse than no answer.

Private markets are a particular focus, from commitment pacing and liquidity planning to fund selection and direct and co-investment analysis. My investment background spans public and private markets, including public equity, fixed income, hedge funds, private equity, private credit, and real assets. My experience covers asset allocation and tactical asset allocation, manager research and due diligence, portfolio construction, multi-strategy hedge fund portfolios, and risk management for institutional portfolios.

On the quantitative side, I build models, analytical tools, data pipelines, and research infrastructure that turn messy, incomplete investment data into structured inputs for decisions. My independent research on regime-aware deep learning for multi-asset allocation is published on SSRN.

Ultimately, I combine institutional investment experience with hands-on AI and quantitative engineering. I translate investment problems into models, agents, and production-ready tools that an investment committee can trust and audit.

AI systems

I build AI systems that investment teams use every day, on the models and cloud platforms large firms already run. Everything below is something I've designed, shipped and maintained.

Read it as

I design and build agentic AI systems: software agents that read documents, use the firm's own tools, check their work and hand every decision that matters to a person. For an investment team, that means the first pass on every LPA, GP report, statement and data feed is done before anyone opens the file. Analysts spend their time on judgment. I take each system from the first idea to a production system the team relies on, with a human in the loop at every step.

I design, build and run agentic systems in production: tool-using LLM agents with typed tool contracts, bounded autonomy, retrieval over firm documents, evaluation gates in CI and explicit human approval steps. They run inside the firm's Azure or AWS tenant and inside Microsoft 365, under the same identity, permissions and audit rules as every other system the firm runs.

What I build

Six capabilities, each one working in a demo on this site

Document intelligence

My systems read LPAs, GP reports, capital account statements, DDQs and CIMs and pull out the figures a team needs: fees, commitments, NAVs, cash flows and key terms. Every number links back to the page and line it came from, so an analyst can check it in seconds. That turns days of manual data entry into a review of exceptions, and it gives the team one source of truth across GPs that all report differently.

Layout-aware parsing of native and scanned PDFs, table reconstruction across page breaks, and extraction into typed fields with units, currency, period and fund identity normalized. Each value carries a page and line reference and is verified against the source text before it is accepted. Values that fail are held for review and never imputed. Field-level accuracy and citation coverage are tracked per document type and per GP template, because a new template is where extraction quality usually drops.

See it in Private Capital Lab and Fund Terms Auditor

Agent workflows

Multi-step systems that research, monitor and reconcile across sources, so analysts start the day from the exceptions. One agent can read a capital call, match it to the books, check it against the liquidity plan and draft the cash movement. It stops for a person to sign off before anything moves money or reaches a client.

Tool-using agents built on the Claude Agent SDK and Model Context Protocol servers, with scoped tools, step and token budgets, explicit stop conditions and hard checks between steps. I use fixed workflows where the path is known and give the model freedom to branch only where the task needs it. Every run is traced and can be replayed from its log with the same inputs, tools and model version.

See it in Agentic Portfolio Monitoring

Evaluation and quality

Every system is tested on real documents whose answers are already known and confirmed by experts, for accuracy, citation coverage and false flags. Any change is retested before it ships, so a team knows the error rate before it relies on the output. The same test set is how I decide whether a new model is better or just newer.

Expert-verified gold sets per document type, stratified by GP template and including planted errors, versioned with the code. Scoring covers field accuracy within tolerance, citation coverage, recall on planted issues and false-positive rate, plus tool-call validity for agents. The regression suite runs in CI on every model, configuration or code change, and a release ships only if no metric drops.

Governance and security

Each user reaches only the data they are allowed to see, and every action leaves an audit trail. Sensitive data stays inside the firm's own cloud tenant, with a clear record of which model did what and who approved it. That is what lets compliance and risk teams say yes.

Entra ID single sign-on and role-based access, with each user's permissions carried into search so a model never reads what that user cannot open. Private networking, managed secrets and customer-managed keys in the firm's Azure or AWS tenant. Append-only logs record model, version, inputs, outputs, tools called and approver for every action, retained under the firm's records policy.

See it in Agentic Portfolio Monitoring

Data foundations

I connect portfolio systems, accounting, market data vendors and data warehouses into one reconciled source. Models then work from the same numbers the investment and operations teams sign off on. Without this, AI just produces faster versions of the same spreadsheet disagreements.

Feeds from portfolio, accounting and market data systems land in Snowflake or PostgreSQL, scheduled with Airflow and modeled in dbt with tests on keys, freshness and reconciliations. Agents read governed views through typed tools, never raw tables, so every number traces back to a source system and a load time. Extracted document data flows back into the same models with its citations attached.

See it in Private Capital Lab

Quant and machine learning models

Forecasting, regime models and portfolio optimization built for allocation decisions. This includes my published research on deep learning for multi-asset portfolios. Agents call these models as tools, so a recommendation rests on tested math and the language model only explains it.

PyTorch models validated walk-forward with purged splits to avoid look-ahead, regime models that learn soft market states, and optimization with Black-Litterman, resampled frontiers and risk budgets. Results are reported against simple baselines with uncertainty. The models are exposed to agents as versioned tools with fixed inputs and outputs, so the same question always gets the same numbers.

Measured on the demos on this site

How these are measured
Extraction accuracy
Share of verified fields where the extracted value matches the confirmed answer within a stated tolerance.
Citation coverage
Share of extracted values whose page and line reference points to text that actually contains the value.
Planted issues caught
Errors placed in the documents on purpose, such as a wrong fee or a broken roll-forward, that the system flagged for review.
False-flag rate
Share of clean checks that were flagged anyway. A useful system keeps this near zero so reviewers trust the flags.
