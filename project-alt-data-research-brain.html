Alternative-Data Research Brain

2026
Applied AI · LLM Research System
Deployed on Azure Container Apps

A research system for a long/short equity team. You type a ticker; it pulls fresh material from six public sources Wall Street indexes poorly, has an LLM read every item, and writes a short, cited, position-ready note. It then surfaces cross-source connections an analyst would not find reading any single feed, and checks that read against SEC fundamentals and price momentum. The interactive panels below run the real control flow, including the citation validator and the repair loop.

Problem & Motivation

Sell-side research is a commodity. Every fund reads the same notes, listens to the same earnings calls, and talks to the same expert networks. The edge sits outside that loop: the social thread where power users are quietly leaving a product, the GitHub issue where a named customer flags a real problem, the trade-press piece that names an account the company has not disclosed. That signal is real, but it is scattered across dozens of noisy places, and reading them all costs an analyst half a day per name.

The brief was to get an analyst up to speed on a name in fifteen minutes from sources that are not well indexed, and to do the hard part: surface connections across sources. The bar was that the analyst walks away with at least one thing they did not already know and could not have found easily on a terminal.

Why a source failing does not break the page: every source coroutine is wrapped so an exception becomes an empty list plus an error status. The Brain Summary and its Citation Validator

The summary is structured around the decision a PM makes, not as a topic-by-topic recap. Every claim sentence must carry at least one [id] pointing at a real ingested item. Click any citation chip to see the underlying source item.

Use Inject a hallucination to make the model cite an item that does not exist. That is the failure this system is built to catch: the validator cross-checks every cited id against the real item set, returns the specific error, and the orchestrator runs one repair pass with that error fed back.

Design choice: no buy/sell rating. The system sees alternative data only, not the PM's model, sizing or portfolio fit, so a rating would be wrong by construction. The position read says what the data argues for or against, with citations and a confidence, and leaves the call to the PM. A confident wrong rating costs far more than a useful read with no rating.

The Connections Engine

Keyword similarity is good at finding items that share words and bad at telling a real connection from topical adjacency. So similarity is only a candidate generator. Each candidate pair goes to the model as a judge, with only those two items and a prompt that explicitly separates "shares keywords" from "same underlying story". Drag the confidence gate to see what the analyst would actually be shown.

Two passes rather than one, for three reasons. Cost: judging every pair of 30 items is 435 calls; the candidate filter caps it near a dozen. Quality: two items with a focused question produce a sharp judgment where thirty at once produce hedging. Composability: the similarity stage swaps for embeddings without touching the judge.

System Overview

Two analytical layers, built in sequence and shipped side by side behind one door:

  • Version 1, the alt-data brain. One page. Six sources ingested concurrently, every item summarised and scored, a synthesised Brain Summary with clickable citations, and a Connections view. Closed-world chat and print-to-PDF included.
  • Version 2, the research terminal. The same brain wrapped in four tabs: a 30-second cross-tab Summary, the Alternative Data brain, Fundamentals built from SEC XBRL, and Momentum computed from prices. Chat reasons across all four.
  • The portal. A thin FastAPI gateway with an email allowlist, a signed session cookie, and a reverse proxy hosting both versions behind one HTTPS URL so a reviewer can compare them.

Source Selection

The brief said three sources done well beat eight done badly. Six were chosen because each sees something the others cannot, and every rejected source has a written reason.

SourceRoleEngineering detail that matters
BlueskyRetail and practitioner chatterReplaced Reddit, whose public endpoints return 403 from datacenter IPs. The AT Protocol search host matters, and its OR operator is unreliable, so the module issues one request per distinctive term and merges, with an engagement floor.
Trade pressNiche publisher coverageA headline subject gate requires the company name, ticker or alias in the title, and reports how many items it dropped. Without it, sector roundups flood the feed.
GitHubOperational truthIssues and releases on company repos plus global code search for product mentions. Release cadence and a named customer filing a bug are the hardest signals to fake. A token raises the rate limit from 60 to 5,000 per hour.
Hacker NewsEarly narrativeFull-text search across stories and comments. The Algolia query does not support boolean OR, so the module passes the single most distinctive term and uses optional words for the rest.
XReal-time sentimentThe one paid source. A regex pre-filter drops pump and FOMO content before any LLM call; verified or large accounts bypass it, because a real analyst's price target shares vocabulary with retail noise.
SEC EDGARAuthoritative anchorRecent 8-K, 10-Q, 10-K, Form 4 and 13F from the submissions API, CIK resolved dynamically. Everything else is opinion from someone with an agenda.

Rejected, with reasons: workforce and compensation data (real alpha, no public API, needs a licensed feed; top roadmap item), app-store reviews (licensed wrappers), podcast transcripts (offline speech-to-text, out of the time box), Stack Overflow (built, tested, dropped: volume collapsed and the signal duplicates GitHub), Stocktwits (public stream now gated).

Keeping It Honest

A confident wrong synthesis is worse than no synthesis. Five layers guard against it:

  • Closed-world prompts. Every synthesis prompt may assert only what is in the supplied items and must say "evidence is thin" rather than infer. Chat answers "the current data doesn't show that" instead of falling back on training knowledge.
  • Citation validator with a repair loop. Demonstrated above. If the repair still fails, the original is kept and logged rather than shipping something worse.
  • An LLM judge for connections. Similarity only proposes; the judge decides, and low-confidence pairs are dropped before the analyst sees them.
  • A UI cross-check. The frontend re-checks every citation chip against the valid id set. Anything else renders as plain text, so a missed hallucination cannot become a misleading link.
  • A house writing standard. One shared style block imported by every analytical prompt: assume nothing, never fabricate a number or name, a banned filler list, and a measured tone that leads with the point.

Reliability, Concurrency & Scale

  • Six sources fetch concurrently; per-item summaries and connection judges run under a semaphore sized to the API rate tier. Tickers share no state, so a scheduler can fan out across all of them and the rate limit, not the architecture, is the bottleneck.
  • Every model call is wrapped in exponential-backoff retries. A failed item summary falls back to its title at relevance 1. A failed Brain call saves the snapshot with an honest empty state. A failed judge drops one connection and the rest survive.
  • State is one JSON file per ticker, written temp-then-rename so a reader always sees a complete old or new snapshot, never a torn one. Every item carries a short, stable, citable id derived from a hash of its source identifier, which is what makes cross-refresh dedup work.
  • Moving from nine tickers to two hundred is operational, not architectural: refresh becomes a scheduled job calling the same function, snapshots move to object storage by swapping two functions in the storage module, and dedup extends to a global content hash.

A database replaces flat files at three triggers: cross-ticker queries, a high concurrent write rate from a large scheduled refresh, or a need for full audit history. For nine tickers, files were the right call and the Pydantic model is the schema.

Access & Security

  • Email allowlist read from an environment secret into a set at startup, compared case-insensitively, never sent to the browser. A non-listed email gets a generic failure so the list cannot be enumerated.
  • Session is a signed, HttpOnly, SameSite cookie, Secure in production, expiring after eight hours. Unauthenticated page requests redirect to login; unauthenticated API calls get a clean 401 so a stale request fails instead of silently receiving login HTML.
  • Both versions run as separate OS processes because they share a package name. Separate interpreters avoid module shadowing and let each build run byte-for-byte as written. The originals are vendored untouched; the only patch is a base tag plus relative API paths.
  • Secrets are injected at runtime and never baked into the image.

The limit is stated honestly: anyone who knows an allowed address can enter. The URL and the address list are the secrets. A one-time-code step slots in without re-architecting.

What I Would Build Next

  • Embedding-based candidate generation as a drop-in for TF-IDF, once cross-ticker queries justify a vector store.
  • A licensed workforce-data feed, which is where the earliest signal on reorganisations lives.
  • A one-time-code login step and object storage for snapshots.
