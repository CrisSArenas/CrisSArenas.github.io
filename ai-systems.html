Architecture

AI Systems

Every demo in the Stack runs on the same agent architecture. Agents do the gathering, checking and modeling. They cite every number, they stop at hard gates, and people make the decisions. This page describes the design, how it fails, and how it is measured.

1. The problem

Most of an investment team's week goes into gathering and checking, not deciding. Capital account statements arrive as PDFs on different templates. Fee lines need recomputing against the LPA. A DDQ runs to dozens of pages and contradicts last year's letter in a footnote. A co-invest window closes before the diligence does. The decision at the end is usually a few sentences long. The work before it is days.

Language models can read those documents, but a fluent answer is not the same as a correct one. In investing an answer you cannot trace is worse than no answer, because someone will act on it. So the systems I build follow three rules:

  • Cite or stop. Every number taken from a document carries the page and line it came from. A number without a citation does not move downstream.
  • Check before acting. Extracted numbers are reconciled against each other and against the data model. Limits and stale data trigger hard gates that no agent can talk its way past.
  • Defer to people. Agents propose. A person approves, and every step is written to a tamper-evident log.

Each demo in the Stack runs this pipeline as a deterministic simulation over synthetic documents for fictional funds and companies. There are no live model calls on this site. The control flow is the real one: plan, call tools, extract, cite, validate, flag, approve, log.

2. Agent roles and orchestration

Agents get narrow roles with explicit inputs and outputs. A narrow role is easier to test, easier to evaluate, and fails in a way you can see.

Planner

Turns the task into a dependency graph of steps: which documents to classify, which fields to extract, which checks must pass before anything is proposed.

Specialists

Document classifier, terms extractor, statement extractor, consistency checker, recomputation agent, memo drafter. Each calls deterministic tools for math (the shared tested math library), never its own arithmetic.

Verifier

The citation validator and the reconciliation agent. They sit on the graph's only path to the output, so no specialist can skip them.

Human reviewer

Approves or rejects each flag and proposal. Their decision, not the agent's, decides what reaches a query letter, a trade list or a memo.

Steps run in dependency order. Independent steps can run in parallel, and a step only starts when every input it depends on has passed verification. When a step fails, the failure is local: the step is marked blocked with its reason, its dependents do not run, and the rest of the graph continues. The Agentic Portfolio Monitoring demo shows a thirteen-agent graph with its critical path.

3. Citation-bound extraction and the validator

Extraction returns structured fields, each with a value, a unit and a citation of the form document, page, line. The validator then checks every field and every claim in a drafted note:

  • The citation resolves: the document exists, the page exists, the line exists.
  • The cited line contains the value, in a form the parser recognises (for example 1.75%, $1,250,000 or (0.4)).
  • Claims in drafted text carry at least one resolving citation. Uncited claims are blocked, not softened.

Blocked items go to the agent log with the reason. They never reach a memo or a query letter. In the demos you can click any citation to open the source document at the cited line.

4. Reconciliation checks on extracted numbers

A number can be correctly extracted and still be wrong. Reconciliation checks catch that by testing identities the numbers must satisfy:

CheckIdentityWhere
Capital account roll-forwardopening NAV + calls - distributions + gains = closing NAVPrivate Capital Lab
Fee recomputationreported fee = rate x basis x days/365 - offsetsFund Terms Auditor
Commitment ledgercalled + unfunded = commitmentPrivate Capital Lab, Secondaries Desk
Carry waterfallLP + GP distributions = total distributionsFund Terms Auditor
Value creation bridgeEBITDA growth + multiple + deleveraging = equity gainCo-Investment Underwriter

A failed identity becomes a break with its size and both citations, and goes to a person.

5. Hard gates

Hard gates are rules in code, outside any model. An agent cannot override them by reasoning about them.

  • Limits. Policy ranges, liquidity floors and concentration limits are checked before any proposal is shown. A breach blocks the proposal and escalates it.
  • Stale data. If a price or a NAV is older than its tolerance, automatic actions stop and the item needs a person.
  • Compliance. A proposed trade is re-checked against the rulebook as if it had already been executed.

6. Human approval and the tamper-evident audit log

Every flag and proposal is an approval card with its evidence and citations. Approve and reject are both decisions, and both are logged. The log is hash-chained: each entry includes a hash of the entry before it, so changing any past entry breaks every hash after it. Each demo exports its log as JSON.

7. Evaluation

Each demo ships a hand-labeled ground-truth file for its synthetic documents, kept separate from the documents and from the pipeline. The evaluation panel in each demo computes, in the page, against those labels:

  • Extraction accuracy: share of labeled fields extracted with the right value.
  • Citation coverage: share of extracted fields whose citation resolves to a line that contains the value.
  • Detection and false-flag rate: for seeded breaks and inconsistencies, how many were caught, and how many clean items were flagged.

Results are recomputed by each demo's own evaluation panel on every load. The table above is collected from those panels by tools/collect-eval.mjs.

9. What changes in a production deployment

  • Model calls. Extraction and drafting steps call a model through a gateway with structured output schemas, fixed prompts under version control, and low temperature. The deterministic tools, validator, gates and math stay exactly as they are here.
  • Data access. Documents come from portals, administrators and data rooms through read-only connectors into the same normalized data model.
  • Permissions. Agents get the narrowest access their role needs. Approvals map to named people and roles.
  • Monitoring. Accuracy, citation coverage and false-flag rates are tracked on a labeled set that grows with every reviewed document, and drops trigger review.
